# Конфигурация DronT16

Единый рабочий файл конфигурации проекта — `config/dront16.toml`.

Каждый параметр должен иметь комментарий на русском языке. Значения по
умолчанию и безопасные ограничения хранятся рядом с параметрами. Секреты,
ключи и персональные данные в конфигурационные файлы проекта не добавляются.

Каждый модуль получает только свою секцию единого TOML через загрузчик
`src/configuration.py`. Модули не открывают TOML самостоятельно и не хранят
дублирующиеся параметры в отдельных файлах.

Секция `[video]` задаёт только вывод: J7, HDMI и диагностический веб-просмотр.

Секция `[camera]` задаёт единый цифровой видеовход. `source = "auto"` означает OV5647
через Picamera2/libcamera на Raspberry Pi и USB-камеру через OpenCV на
ноутбуке. Рабочий CSI-поток — `1296x972 @ 46.3 fps`, формат `RGB888`: в массивах
Picamera2 он расположен как B,G,R, поэтому сразу совместим с OpenCV и не
требует отдельной перестановки цветовых каналов.
Значение `source = "csi"` принудительно выбирает Picamera2, а путь, имя файла
или числовой индекс — OpenCV.

Вложенная секция `[camera.zoom]` задаёт цифровое приближение через crop: `level
= 1.0` оставляет весь кадр, а `level = 2.0` оставляет центральную половину
ширины и высоты с последующим увеличением до исходного размера. Секция
`[camera.image]` задаёт отражение, поворот, контраст, яркость и резкость.
Секция `[camera.lens]` применяет коррекцию дисторсии только при наличии заранее
созданного NPZ-файла с `camera_matrix` и `dist_coeffs`.

Ручная настройка камеры запускается командой `./camera.sh`. Страница
`http://IP_RASPBERRY:8090/camera` сохраняет только параметры `[camera]`.
Сервис не входит в автозагрузку; после сохранения нужно перезапустить `run.sh`
или `dront16.service`, чтобы видеопроцесс прочитал новые параметры.

Секции `[msp]` и `[failsafe]` в `dront16.toml` предназначены для отдельного
канала чтения датчиков Betaflight и контроллера удержания после потери связи.
После CH7 failsafe удерживает высоту и горизонт, выполняет разворот 180 градусов
по фактическому yaw и ждёт восстановления CH7. Автоматического снижения и
режима посадки в проекте нет. Параметр `failsafe.mode` принимает `CH7` для
стендовой имитации или `real` для перехода по тайм-ауту отсутствия CRSF-кадров.
В `real` Raspberry не может принять DISARM по радио во время потери; при отказе
самой Raspberry или её UART Betaflight должен сохранить собственный failsafe.

Секция `[visual_servoing]` относится только к верхнему положению CH6. Она
задаёт последовательность наведения yaw, подтверждение высоты и ограниченный
pitch по изменению масштаба ранее захваченной цели. `output_mode = "real"`
включён только для текущего стенда со снятыми винтами; `output_mode = "dry-run"`
оставляет реальный RC-кадр неизменным; real разрешается после
стендовой проверки направлений и стабилизирующего режима Betaflight.

Свежесть ATTITUDE и ALTITUDE проверяется раздельно. Параметр
`stabilization_channel = 0` отключает автоматическое переключение
ANGLE/HORIZON; включать AUX можно только после проверки Betaflight.

При ARM модуль фиксирует высоту `ALTITUDE_ZERO`. Параметры
`level_roll_tolerance_deg`, `level_pitch_tolerance_deg` и `level_hold_s` не
разрешают разворот, пока дрон не выровнен и не удерживает горизонт заданное
время.

Утверждённый MSP-порт Raspberry — `/dev/ttyAMA1` через GPIO0/1, физические
pin 27/28; текущий CRSF остаётся на `/dev/ttyAMA0`, pin 8/10.

Секция `[osd]` в `dront16.toml` содержит размеры центрального квадрата,
перекрестия, рамок, точки цели и подписей экранного OSD. Для уменьшения квадрата изменяется
параметр `osd.capture_box_size`.

В разделе `[osd.output]` единого файла параметр `video_standard` задаёт только
стандарт аналогового выхода J7. Для рабочего выхода используется `NTSC`,
поэтому Raspberry выбирает режим `720x480i`. Этот размер не меняет разрешение
CSI-захвата: готовый кадр масштабируется адаптером J7 только перед выводом.
