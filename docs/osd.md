# Цифровой OSD и вывод режимов

## Принцип

Видеопоток дрона и тракт камеры передатчика не входят в проект DronT16.
Raspberry Pi 5 не захватывает, не перекодирует и не пересылает видеопоток
дрона. У Raspberry есть собственная камера для алгоритма сопровождения.

Raspberry Pi работает только с цифровым OSD:

```text
Полётный контроллер
        ↓ цифровой OSD
UART 1 → Raspberry Pi 5 → UART 2
                              ↓
                         передатчик

Камера Raspberry Pi → DronT16 → данные сопровождения в OSD
```

Raspberry должна пропускать штатные OSD-данные без искажения и добавлять только
свои элементы: режим работы, состояние цели, рамку/маркер и линию направления
в формате, который поддерживает конкретная система OSD.

## Вывод режима работы

Один и тот же логический статус выводится одновременно:

- на тестовый HDMI-экран ноутбука — для отладки;
- в цифровой OSD-поток пилота — для рабочего полёта.

Источник статуса общий, а способы отображения разные. Ошибка веб-морды или
отладочного HDMI не должна изменять штатный видеотракт передатчика.

## Предоставленные пины

Для двух UART Raspberry Pi предварительно указаны физические контакты: `7`,
`8`, `10`, `29`.

Роли пар, направление RX/TX, уровни сигналов, общий GND и соответствие UART
пока не подтверждены документацией конкретной платы. До проверки схемы и
измерения уровней внешние сигналы к Raspberry не подключаются.

## Текущий этап

Протокол цифрового OSD и формат добавляемых элементов пока неизвестны.
Модуль UART/OSD будет реализован после подтверждения полётного контроллера,
передатчика, протокола и электрической схемы. До этого работает только
локальная визуализация на HDMI и веб-просмотр собственной камеры Raspberry.
