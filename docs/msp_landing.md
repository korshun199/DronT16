# Чтение датчиков и посадка по Betaflight

Модуль посадки находится в `src/control/landing.py`, а двусторонний read-only
канал датчиков — в `src/protocols/betaflight_msp_link.py`.

## Каналы

Текущий CRSF-мост не меняется:

```text
приёмник TX -> Raspberry pin 10 / текущий CRSF UART
Raspberry pin 8 -> FC UART1 RX / RC-команды
```

Для MSP утверждена отдельная схема:

```text
FC UART2 TX / PA2 -> Raspberry pin 28 / GPIO1 / UART1 RX
FC UART2 RX / PA3 <- Raspberry pin 27 / GPIO0 / UART1 TX
FC GND            -> Raspberry pin 30 / GND
```

На Raspberry используется `/dev/ttyAMA1`; для GPIO0/1 потребуется overlay
`dtoverlay=uart1-pi5`. На полётнике MSP включается только на UART2. Текущий
UART1 Betaflight остаётся CRSF-каналом. GPIO0/1 также являются HAT-ID I²C, поэтому
их нельзя одновременно использовать как HAT-ID и MSP-UART.

## Что читается

Используются ответы MSP v1:

- `MSP_ATTITUDE`: крен, тангаж, курс;
- `MSP_ALTITUDE`: высота и вариометр;
- CRC и возраст каждого типа данных проверяются отдельно до передачи их
  контроллеру посадки. Свежий крен не считается подтверждением свежей высоты.
- При переходе CH5 в ARM сохраняется `ALTITUDE_ZERO`, а дальнейшая высота
  считается относительно этой точки.
- Снижение разрешается только после удержания крена и тангажа в заданных
  пределах стабилизации.

При входе в `TAKEOVER` газ не перескакивает сразу к `level_throttle`: он
плавно переходит от последнего значения пилота с ограничением
`takeover_throttle_step_per_s`. Одновременно работает защита от набора:
при превышении высоты `climb_guard_altitude_error_m` или вариометра
`climb_guard_vario_m_s` газ ограничивается значением
`climb_guard_max_throttle`. Эти параметры находятся в `[landing]` и должны
проверяться сначала на стенде.

## Состояния

```text
LIVE -> TAKEOVER -> LEVELING -> DESCENT -> LANDED
                         \-> FAULT
```

`DISARM` CRSF-моста имеет приоритет над всеми состояниями. Raspberry формирует
только RC-кадры для Betaflight; PWM моторов и PID остаются внутри FC.

При устаревших или неполных MSP-данных состояние становится `FAULT`. В режиме
`HOLD` последний безопасный RC-кадр удерживается; в режиме `DISARM` формируется
кадр с DISARM. Автоматическая посадка по одному барометру —
только стендовый прототип: для реального определения земли нужен дальномер или
проверенный штатный режим Betaflight.

## Включение после подключения

Для текущего стендового испытания MSP и посадочный автомат включены:

```toml
[msp]
enabled = true

[landing]
enabled = true
```

Все
изменяемые параметры посадки находятся в секции `[landing]` и снабжены русскими
комментариями.

Команда Betaflight после проверки проводов:

```text
serial 1 1 115200 57600 0 115200
save
```

## Проверки

Локальные проверки без оборудования:

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile src/protocols/betaflight_msp_link.py src/control/landing.py scripts/crsf_bridge.py
```

Аппаратная проверка начинается с подтверждения MSP-пакетов в журнале:

```text
[SENSOR] altitude=... vario=... roll=... pitch=...
```

До появления таких строк посадочный режим включать нельзя. Отдельно нужно
проверить направление коррекции крена/тангажа и заранее настроить в Betaflight
режим ANGLE/HORIZON; автоматическое переключение AUX по умолчанию отключено.
