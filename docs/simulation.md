# Ноутбучная модель Raspberry Pi 5

Пока бортовой платы нет, вся логика DronT16 моделируется на ноутбуке.

## Соответствие устройств

```text
Ноутбук                         Будущая система
USB-камера ноутбука        →    камера Raspberry Pi 5
Python/OpenCV на ноутбуке  →    DronT16 на Raspberry Pi 5
HDMI-монитор ноутбука       →    веб-морда DronT16
Клавиши 1..4               →    программный тестовый вход
```

## Ограничение модели

В пункте `DIRECT` USB-камера ноутбука является источником чистого видео для
тестового экрана. После команд «Захватить» и «Следить» кадр получает наложение
статуса и маркера цели. Настоящий пульт, его электрический вход и переключение
J7 в ноутбучной модели не проверяются. Команды полётнику не отправляются.

Это только модель цепочки обработки. Реальный видеопоток дрона и камера
передатчика в работу не включаются: в настоящей системе они проходят своим
штатным трактом, а Raspberry выдаёт собственное видео через J7.

## Команды симуляции

- `1` — программная команда `DIRECT`;
- `2` — программная команда «Захватить»; пилот наводит камеру, чтобы объект
  оказался в центральном квадрате;
- `3` — программная команда «Следить»;
- `4` — программная команда «Отбой».

После появления Raspberry Pi клавиатурный источник заменяется адаптером
команды стика от выбранной системы управления. Машина состояний, обработка потери цели и правила запрета
переключения цели при этом не меняются.

## Диагностика и конфигурация

При захваченной цели `./run.sh` выводит в терминал две строки:

- зелёную — координаты центра цели в пикселях, нормализованное отклонение и
  углы относительно камеры при команде `2` «Захватить»;
- красную — те же координаты и углы при команде `3` «Следить».

Параметры расчёта находятся в `config/follow.toml`. Реальный UART и отправка
команд MSP отключены до проверки конкретного полётного контроллера.

## Два представления

В текущей симуляции обработанный кадр выводится только в веб-морду, открытую на
HDMI-мониторе ноутбука. Отдельное окно OpenCV для пилотского изображения не
используется.

В рабочей системе тестовый экран ноутбука заменяется видеовыходом собственной
камеры Raspberry Pi через J7,
переданным на передатчик. Веб-морда остаётся отдельным диагностическим каналом.

HDMI-монитор ноутбука показывает окно браузера с веб-мордой. Координаты окна
OpenCV для пилотского изображения на текущем этапе не используются.
