# Архитектура DronT16

## Цель документа

Зафиксировать текущую архитектуру компонентов и границы безопасного этапа.
Видео и CRSF-мост уже работают на стенде; чтение датчиков Betaflight подготовлено
через отдельный MSP-UART, а автоматическая посадка пока выключена.

## Компоненты

- `video` — получение кадров и временных меток;
- `target` — захват области по команде пилота и сопровождение только выбранной цели;
- `interface` — рамка, линия, состояния и предупреждения на экране;
- `web` — просмотр кадра, состояния и передача тестовых команд через браузер;
- `osd` — наложение статуса, указателя, рамки и линии курса на собственное видео;
- `control` — режимы, ограничения, тайм-ауты и ручной приоритет;
- `protocols` — CRSF и read-only MSP-обмен с полётным контроллером.

Команды имеют единый внутренний формат. На ноутбуке источник команд — клавиши
`1..4`; на Raspberry Pi 5 источник будет заменён адаптером команд от
полётного контроллера. Остальная логика системы от источника команд не зависит.

Видеопоток дрона и камера штатного передатчика находятся вне системы.
Raspberry Pi использует собственную камеру и работает по пяти пунктам:

1. `DIRECT`: камера напрямую выдаётся на J7;
2. `CAPTURE`: по команде «Захватить» на J7 выдаётся камера с рамкой и
   наложением;
3. `FOLLOW`: на J7 остаётся обработанное видео, а команды сопровождения идут
   полётнику отдельным каналом;
4. при стендовом CH7 takeover Raspberry подавляет свежие RC-кадры и повторяет
   последний полный кадр; включённый отдельно посадочный модуль может менять
   RC-команды по данным MSP;
5. после восстановления связи или команды «Отбой» система переходит в
   `DIRECT`.

J7 используется только для видеосигнала. Команды и состояние полётнику идут
отдельным параллельным каналом.

На ноутбуке проверяются только обработка USB-видео, захват
цели и наложение через веб-морду, открытую на HDMI-мониторе. Клавиши или веб-кнопки `1..4` являются программным тестовым
входом, но не заменяют настоящий пульт. Приём команды стика и переключение J7
проверяются только на Raspberry Pi с подключённой системой управления.

Сопровождение цели не должно напрямую управлять моторами или выдавать команды
полётному контроллеру. Между оценкой цели и управлением располагается отдельный
ограничитель команд.

Все конфигурации проекта хранятся в формате TOML. Каждый параметр сопровождается
комментарием на русском языке; секреты и данные конкретных устройств в них не
хранятся.

## Состояния

```text
Ожидание → Захват цели (CAPTURE) → Следить
                         ├→ Автопилот: запрещён
                         ├→ Отбой → Ожидание
                         └→ Потеря цели → Цель потеряна
                                           └→ RETURN при потере связи → DIRECT

Из состояния «Цель потеряна» можно выйти только новой командой «Захватить».
```

Переход в «Автопилот» разрешается только для ранее захваченной цели. Переход к
новой цели без команды «Захватить» запрещён.
