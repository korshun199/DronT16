# Архитектура DronT16

## Цель документа

Зафиксировать границы компонентов до начала разработки. Конкретные протоколы и
драйверы не выбираются, пока не подтверждены оборудование и система управления.

## Компоненты

- `video` — получение кадров и временных меток;
- `target` — захват области по команде пилота и сопровождение только выбранной цели;
- `interface` — рамка, линия, состояния и предупреждения на экране;
- `web` — просмотр кадра и состояния через браузер без команд управления;
- `osd` — перехват цифрового OSD по двум UART и добавление статуса DronT16;
- `control` — режимы, ограничения, тайм-ауты и ручной приоритет;
- `protocols` — будущий обмен с пультом и полётным контроллером.

Команды имеют единый внутренний формат. На ноутбуке источник команд — клавиши
`1..4`; на Raspberry Pi 5 источник будет заменён адаптером команд от
полётного контроллера. Остальная логика системы от источника команд не зависит.

Видеопоток дрона находится вне системы. Raspberry Pi использует собственную
камеру для сопровождения, а на пилотский видеотракт передаёт только изменённый
цифровой OSD между двумя UART.

До появления платы эта схема моделируется на ноутбуке: USB-камера заменяет
камеру Raspberry, клавиши `1..4` заменяют команды полётного контроллера, а
HDMI-монитор показывает тестовое изображение пилота с наложенным OSD.

Сопровождение цели не должно напрямую управлять моторами или выдавать команды
полётному контроллеру. Между оценкой цели и управлением располагается отдельный
ограничитель команд.

## Состояния

```text
Ожидание → Захват цели (CAPTURE) → Следить
                         ├→ Автопилот: запрещён
                         ├→ Отбой → Ожидание
                         └→ Потеря цели → Цель потеряна → Ожидание

Из состояния «Цель потеряна» можно выйти только новой командой «Захватить».
```

Переход в «Автопилот» разрешается только для ранее захваченной цели. Переход к
новой цели без команды «Захватить» запрещён.
