# Стендовый CRSF takeover

Модуль предназначен только для наземного испытания с винтами, снятыми с дрона.
Приёмник продолжает передавать CRSF в Raspberry, а Raspberry программно решает,
какой кадр отправить на RX полётника.

## Состояния

- `LIVE` — каждый корректный входной кадр передаётся без изменения.
- `TAKEOVER` — при CH7 и подтверждённом ARM свежие кадры подавляются, а из
  последнего полного кадра формируется плавная рампа газа до CRSF-ноля.
- `DISARM_RELEASE` — DISARM немедленно отправляется в полётник, затем живой
  поток возвращается; новый takeover блокируется до возврата CH7.

Для текущей аппаратуры используются:

- CH5: `>=1700` — ARM, `<=700` — DISARM;
- CH7: `>=1700` — запрос takeover, `<=700` — обычная связь;
- UART Raspberry: `/dev/ttyAMA0`, pin 10 RX от приёмника, pin 8 TX к FC UART1 RX;
- скорость: `420000` бод.

## Запуск и журнал

Единая команда запуска:

```bash
./run.sh
```

На Raspberry журнал systemd:

```bash
sudo journalctl -u dront16 -f -o cat
```

Общий файл: `simulator_filesafe.log`.

В журнале должны быть видны `LIVE`, `TAKEOVER`, `THROTTLE RAMP`, `DISARM` и
`TAKEOVER -> LIVE`. Команды имеют пометку `SIMULATED` только в текстовом
симуляторе; CRSF-кадры управляемого моста являются реальным стендовым выходом.

## Безопасный порядок испытания

1. Снять все винты и закрепить дрон.
2. Включить CH5 в ARM, газ установить примерно на 30%.
3. Запустить `run.sh` и убедиться в режиме `LIVE`.
4. Включить CH7 и проверить повтор сохранённого кадра.
5. Вернуть CH7 и проверить живое управление.
6. Повторить takeover и перевести CH5 в DISARM.
7. Проверить немедленную остановку моторов и возврат живого канала.
