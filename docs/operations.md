# Эксплуатация Raspberry Pi

## Один источник подключения

Фактический адрес Raspberry Pi, путь проекта, имя службы и путь журнала лежат
только в локальном файле `config/deployment.toml`. Он не публикуется в Git.
Шаблон для нового ноутбука — `config/deployment.example.toml`.

Приватный SSH-ключ всегда находится вне проекта, обычно
`~/.ssh/id_ed25519`. Скрипты не копируют ключи на Raspberry и не хранят пароли.

## Единая команда

Все проверки Raspberry выполняются из корня проекта одной командой:

```bash
./scripts/rpi.sh check
```

Она показывает имя и адрес Raspberry, её локальное/UTC-время, состояние NTP,
службы `dront16`, процессы и наличие журнала.

| Команда | Назначение |
|---|---|
| `./scripts/rpi.sh check` | Проверить доступ, время, службу, процессы и журнал. |
| `./scripts/rpi.sh log 120` | Показать последние 120 строк журнала. |
| `./scripts/rpi.sh cycle` | Показать последний цикл от ARM до DISARM. |
| `./scripts/rpi.sh copy-log` | Сохранить копию журнала в локальный `runs/raspberry/`. |
| `./scripts/rpi.sh sync` | Показать, какие безопасные файлы будут переданы. Ничего не записывает. |
| `./scripts/rpi.sh sync --apply` | Передать исходники, настройки и документацию на Raspberry. Службу не перезапускает. |
| `./scripts/rpi.sh verify` | Проверить синтаксис и все тесты в окружении Raspberry без перезапуска службы. |
| `./scripts/rpi.sh shell` | Открыть обычную SSH-оболочку. |

Для SSH, проверки Raspberry, журнала и синхронизации используется единый
`scripts/rpi.sh`; отдельного SSH-запускателя нет.

## Правило синхронизации

Перед загрузкой запускается `sync` без `--apply`. Он не меняет Raspberry и
показывает точный список различий. Только затем используется `sync --apply`.

Не передаются `.venv`, логи, `runs`, `backups`, `security`, `security_sample`,
CLI-дампы Betaflight, приватный ключ и локальный `config/deployment.toml`.

После проверенной загрузки новый код начинает использоваться только после
перезапуска службы владельцем:

```bash
sudo systemctl restart dront16
```

## Время

Для сопоставимых логов ноутбук и Raspberry должны иметь NTP-синхронизацию и
единый часовой пояс `Europe/Moscow`. Команда `check` показывает оба признака.
Изменение часового пояса — системная операция и выполняется владельцем:

```bash
sudo timedatectl set-timezone Europe/Moscow
```

## Журнал испытания

Рабочий журнал начинается при ARM и прекращает запись при DISARM. До ARM
сообщения остаются в терминале, но не засоряют файл испытания. Файл не
очищается автоматически: очистка остаётся явным решением владельца. Последняя
команда `DISARM; MOTORS OFF` записывается в файл до закрытия ARM-цикла.
