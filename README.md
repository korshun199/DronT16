# DronT16

Локальная система назначения и сопровождения выбранной пилотом цели для FPV-дрона.

Проект разделён на два этапа применения:

- **T16** — отладочная платформа без управления дроном;
- **Raspberry Pi 5** — будущая бортовая рабочая платформа.

Базовые команды системы: «Захватить», «Следить», «Автопилот» и «Отбой».
Система не распознаёт классы объектов, не ищет новую цель самостоятельно и
после потери цели требует нового явного захвата пилотом.

Текущий этап — безопасный визуальный прототип. Автопилот и обмен с полётным
контроллером отключены до выбора системы управления дроном.

Подробная спецификация находится в [PROJECT.md](PROJECT.md).

Сценарий моделирования Raspberry Pi на ноутбуке описан в
[docs/simulation.md](docs/simulation.md).

## Окружение ноутбука

Основная команда владельца проекта — `./run.sh`. Она сама создаёт `.venv`,
проверяет и при необходимости устанавливает зависимости.

Обычный запуск ноутбучной модели включает локальную веб-морду — это основной
тестовый экран проекта:

```bash
./run.sh
```

После запуска веб-просмотр ноутбука доступен по адресу
[http://127.0.0.1:8080/](http://127.0.0.1:8080/).

Все параметры находятся внутри `run.sh`: источник камеры, режим вывода,
координаты HDMI и веб-порт. Передавать аргументы командной строки не нужно.
Источник `auto` выбирает USB-видеоустройство автоматически, а положение
внешнего HDMI-монитора скрипт пытается определить по выходам HDMI/DP/DVI/VGA.

Для будущего рабочего режима Raspberry Pi 5 параметры также заранее задаются
внутри `run.sh`, после чего запускается та же команда:

```bash
./run.sh
```

Ручные команды ниже нужны только разработчику и обычно владельцу не требуются:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-laptop.txt
```

## Локальный визуальный прототип

Прототип работает с камерой или записанным видео и не отправляет команды
полётному контроллеру:

```bash
python3 -m src.app --source 0
```

Для отдельной проверки вывода на внешний HDMI-монитор можно временно изменить
`DISPLAY_MODE` внутри `run.sh` на `hdmi` и указать координаты в виртуальной
рабочей области Ubuntu. Например, если монитор справа от экрана
ноутбука шириной 1920 пикселей:

```bash
python3 -m src.app --source 0 --display hdmi --hdmi-x 1920 --hdmi-y 0 --fullscreen
```

Координаты зависят от расположения экранов. В зеркальном режиме они обычно не
нужны.

Для рабочего режима Raspberry Pi 5 предусмотрен просмотр через веб-морду
(адрес Raspberry Pi в локальной сети):

```bash
python3 -m src.app --source /dev/video0 --display web --web-host 0.0.0.0 --web-port 8080
```

После запуска страница просмотра доступна по адресу
`http://АДРЕС_RASPBERRY_PI:8080/`. Веб-морда показывает кадр, состояние и
кнопки тестовых команд. Автопилот через неё всё равно не выполняется.

В рабочем режиме Raspberry Pi 5 четыре команды должны поступать от
полётного контроллера через отдельный адаптер. Протокол и электрический
интерфейс пока не выбраны.

В окне видео используются клавиши:

- `1` — захватить объект внутри центрального квадрата;
- `2` — включить экранное сопровождение;
- `3` — запросить автопилот, который пока отклоняется;
- `4` — отбой;
- `Q` или `Esc` — выход.

Путь к видео можно передать вместо индекса камеры:

```bash
python3 -m src.app --source /путь/к/записи.mp4
```

В текущей модели веб-кнопки и клавиши браузера `1..4` являются только
программным тестовым входом. Работу настоящего стика и переключение J7 можно
проверить только на Raspberry Pi. Реальный видеопоток дрона в программу не подаётся: веб-морда (или отдельно
включённый HDMI-режим) показывает собственное видео камеры с наложением DronT16.

Перед захватом наведи камеру так, чтобы объект оказался в центральном квадрате.
Размер квадрата задаётся внутри `run.sh` параметром `CAPTURE_BOX_SIZE`.
